# Публикация Nail Salon API в интернете (HTTPS)

## Важно
Проект — Java/Spring Boot приложение, а не статический HTML/PHP-сайт. Обычные тарифы InfinityFree и другие shared-хостинги, рассчитанные только на PHP, как правило, не запускают постоянные Java/Spring Boot процессы. Для этого проекта используйте хостинг с поддержкой Docker/Java, например Render или Railway, либо VPS. В этой папке подготовлен Dockerfile и шаблон Render.

## Что уже подготовлено в проекте
- Dockerfile собирает приложение на Java 17 и запускает Spring Boot.
- Профиль `prod` подключает PostgreSQL через переменные окружения.
- JWT-секрет берётся из `JWT_SECRET`, а не хранится в исходном коде.
- `server.forward-headers-strategy=framework` позволяет Spring корректно учитывать HTTPS за reverse proxy хостинга.
- H2 остаётся для локального запуска; в production используется PostgreSQL.

## Публикация на Render
1. Создайте аккаунт на https://render.com/ и загрузите проект в GitHub (создайте приватный репозиторий, если не хотите публиковать исходники).
2. В Render нажмите **New → PostgreSQL** и создайте базу данных. Скопируйте Internal Database URL, имя пользователя и пароль.
3. В Render нажмите **New → Blueprint** и выберите репозиторий с проектом. Render обнаружит `render.yaml` и создаст Web Service.
4. Откройте настройки Web Service → **Environment**. Заполните переменные:
   - `DB_URL` — JDBC-адрес PostgreSQL. Пример формата: `jdbc:postgresql://HOST:5432/DATABASE` (возьмите HOST, порт и имя БД из данных созданной БД; не вставляйте обычный `postgres://` без префикса `jdbc:postgresql://`).
   - `DB_USERNAME` — пользователь PostgreSQL.
   - `DB_PASSWORD` — пароль PostgreSQL.
   - `JWT_SECRET` — длинная случайная строка не короче 32 символов. Не публикуйте её и не добавляйте в Git.
   - `SPRING_PROFILES_ACTIVE` должен быть `prod`.
5. Нажмите **Deploy** и дождитесь статуса **Live**. В логах не должно быть ошибок подключения к БД.
6. Render выдаст адрес вида `https://ИМЯ-СЕРВИСА.onrender.com`. Откройте его в браузере. HTTPS и сертификат TLS для стандартного домена Render подключаются платформой автоматически; вручную загружать сертификат в приложение не нужно.
7. Проверьте Swagger: `https://ИМЯ-СЕРВИСА.onrender.com/swagger-ui.html`. Проверьте API: `https://ИМЯ-СЕРВИСА.onrender.com/v3/api-docs`.
8. Для демонстрации авторизации выполните `POST /api/auth/login` с JSON `{"login":"admin","password":"admin123"}`, скопируйте JWT из ответа и нажмите **Authorize** в Swagger. Не оставляйте демонстрационный пароль в публичном production-сервисе: после проверки измените учётные данные/инициализацию и используйте собственные секреты.

## Проверка SSL/HTTPS
- Адрес сайта должен начинаться с `https://`, а не `http://`.
- В браузере нажмите значок слева от адреса → сведения о соединении. Браузер должен сообщать о защищённом соединении.
- Откройте сертификат и проверьте, что он действителен для домена и срок действия не истёк.
- Сделайте скриншоты: страница Swagger с адресной строкой `https://.../swagger-ui.html`; окно сведений о сертификате; успешный ответ `POST /api/auth/login` (токен на скриншоте лучше скрыть частично).

## Если используется другой хостинг
Нужна поддержка Java 17 или Docker, фонового веб-сервиса и переменных окружения, а также PostgreSQL. Уточните это до покупки тарифа. Бесплатные PHP-хостинги не подходят, если не позволяют запускать Spring Boot.

## Что ещё требуется сделать вручную
Автоматически создать аккаунт хостинга, принять условия сервиса, создать БД, развернуть приложение, получить реальный публичный домен и сделать снимки браузера без доступа к вашему аккаунту невозможно. Эти действия выполняются владельцем аккаунта. После публикации впишите фактический URL и добавьте свои скриншоты в отчёт.
